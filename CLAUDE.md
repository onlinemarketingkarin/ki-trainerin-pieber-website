# KI-native Website für Karin Pieber

Eine Website ohne CMS: Die KI liefert strukturierte Daten gegen einen Vertrag, der Renderer macht daraus deterministisch HTML.

**Lies zuerst:**
- `ki-native-website-motor.md`: die Bauanleitung („Website-Motor") mit den sieben Prinzipien und den Stufen
- `docs/entscheidungen.md`: warum das System so gebaut ist und wofür (Weichen, Design, Fakten, offene Punkte)
- `docs/inhaltskonzept.md`: die Texte, SEO-Titel und URLs aller Seiten

## Befehle
```bash
npm start            # Server, http://localhost:$PORT (lokal 3100, siehe .env)
npm run dev          # wie start, lädt bei Änderungen neu
npm test             # node --test, ohne Datenbankdatei und ohne Schlüssel
npm run seed         # Seiten und Navigation aus content/ laden (überschreibt nichts; -- --force überschreibt)
npm run golden       # Goldreferenz der Startseite neu erzeugen (page-types/home/golden.html)
npm run bild -- <datei>  # Bild zu WebP in drei Breiten, Basispfad kommt in ein Bildfeld
```
Cockpit: `http://localhost:$PORT/cockpit` (lokal 3100). Anmeldung über `ADMIN_PASSWORD` in `.env` (mindestens 8 Zeichen, nie committen). Generator (Stufe 4) braucht zusätzlich `ANTHROPIC_API_KEY` in `.env`.

## Regeln, die nie kippen
1. **P1** Die KI produziert JSON gegen ein Schema, nie HTML. Bausteine in `src/blocks/`, Seitentypen in `page-types/`.
2. **P2** Fakten (Adresse, Preise, Links, Zertifikat) stehen nur in `config/facts.json` und kommen als `{{facts.…}}` in den Text. Fehlt einer, erscheint sichtbar `[…]`. Vor dem Livegang darf kein `[…]` auf einer öffentlichen Seite stehen.
3. **P3** Übersichten sind Abfragen. Zahlen werden gerechnet (`facts.abgeleitet`), nie getippt.
4. **P4** Erst die Goldreferenz von Hand (`page-types/<typ>/golden.html`), dann der Generator.
5. **P5** `draft → generated → edited → approved → published → archived`. Was ein Mensch bearbeitet hat (`edited`), wird nicht ohne Force überschrieben.
6. **P6** Nichts Zusätzliches (SEO, Bilder, Analytics, Mail) blockiert eine Veröffentlichung.
7. **P7** Veröffentlichtes liegt unter festen URLs, kein Build-Schritt.
- Farben nie direkt in einen Baustein: alles über Tokens in `config/theme.json`. Signalfarbe Terra ist Signal, nie Fläche. Grund nie reines Weiß.
- Alles, was ein Baustein ausgibt, läuft durch `src/blocks/_util.js` (escapen, `ziel()` für Links).
- Kein Frontend-Framework, kein Build-Schritt. Pfade mit Schrägstrich, nur Node-Skripte, keine Shell-Skripte.
- Nach jeder Änderung an der echten URL prüfen, nicht nur am Quelltext.

## Umgebung
- Das Projekt liegt in **iCloud Drive**. Die SQLite-Datei liegt deshalb außerhalb (`SQLITE_FILE` in `.env`, nicht committen). Jedes Skript, das die Datenbank anfasst, importiert `src/db.js` und liest damit dieselbe `.env`.
- Port 3000 belegt Docker, lokal läuft der Motor auf 3100.
- Betrieb später: IONOS-VPS mit Coolify, Postgres über `DATABASE_URL`. Kein Serverless.
- Schriften (Cormorant Garamond, DM Sans) liegen lokal in `public/fonts/` (Open Font License), keine externen Dienste (steht so im Datenschutzentwurf).
- Bilder liegen in `data/uploads/` (nicht im Repository). Auf dem Server muss das Portrait einmal mit `npm run bild` erzeugt oder ab Stufe 3 im Cockpit hochgeladen werden, sonst fehlt es auf der Seite.
- Seiteninhalt kommt aus `content/pages/*.json`. `npm run seed` lädt nur, was fehlt. Bearbeitetes wird nie überschrieben (P5).
- Das Cockpit (`admin/`) ist Vanilla JS ohne Build-Schritt, eigenes CSS (spiegelt die CI-Token aus `config/theme.json`, siehe Kommentar in `admin/cockpit.css`). Formulare entstehen aus dem Baustein-Schema (`admin/felder.js`), nie handgeschrieben.
- Mailversand fürs Kontaktformular optional über `SMTP_URL` (nodemailer). Ohne SMTP_URL wird die Anfrage trotzdem gespeichert, nur die Mail scheitert laut protokolliert (P6).
